# 점검 보고 — 데이터 파이프라인·변수 사전 (영역 6)

점검 대상: collect.py, build_master.py, adapters/*, engine/registry.py, engine/store.py, engine/repair.py, engine/calendar.py, engine/experiment.build_dataset, data/variable_master.xlsx, data/versions/*, docs/GUIDE.md 데이터·발표시차 장, tools/lag_evidence.py, tools/lag_shift.py. 저장소는 읽기만 했고 계산은 /tmp/rv6_data/ 에서 했다(데이터 버전 20261103T141116Z 기준).

## 1. 총평
발표시차 정렬 자체는 잘 설계돼 있고(align_to_calendar 단일 지점, 독립 구현 대조 테스트), 근거 표(lag_evidence.py)와 마스터 값이 65/65 일치한다. 그러나 "값이 맞다" 쪽에서 새 문제가 있다. (가) 마스터의 H2(주택건설인허가)는 월별 값이 아니라 연초 누계인데 기본 변환이 pct 라 매년 1월 −90% 변화가 생긴다. (나) 일간 변수는 월간·주간 모델에 그 달 마지막 하루 변화로 들어가며(월간 KOSPI 수익률과 상관 −0.06), 중복 치환(L1→USDKRW, N12→KR3Y)이 이를 키운다. (다) 평가 구간 3,116 거래일 중 1,169일(37%)이 하루 거래대금 1억 원 미만(2013~2016 중앙값 0.23억)이라 "시가 체결+5bp" 가정은 그 시기에 방어가 어렵다. (라) 가격은 분배금 미반영 원주가라 매년 4월 말 0.2~1.4% 의 예측 가능한 하락이 타겟에 들어 있다. (마) 데이터 버전은 불변이 아니고(11-04 생성 버전이 11-06 에 바뀜), 변수 사전은 해시 없이 가변이며 버전 폴더 registry.csv 는 실험이 쓰지 않는 옛 스냅샷이다. (바) start 를 비운 결과 5개는 2007년 8일짜리 토막 자료 위에서 학습이 시작돼 "하루 수익률 +25%" 같은 값이 들어갔다. 결론("신호 없음")을 뒤집을 누출은 찾지 못했지만 논문 데이터 절에 쓰기 전에 위 항목 정리가 필요하다.

**중대 1. H2(주택건설인허가실적)는 연초 누계 시계열인데 마스터는 월별 값으로 취급(transform pct)**
- 근거: data/uploads/macro_seoul34.xlsx df_M H2 — 2021-12 545,412 → 2022-01 39,614 → 2022-02 70,128 → … → 2022-12 521,791 → 2023-01 29,739. 2~12월 전월 대비 증가 비율 100%, 1월마다 −92%. 2022-12 값 = 2022년 연간 인허가 규모. 마스터 H2: unit 호, transform pct, GUIDE 301행 동일.
- 영향: pct 로 쓰면 매년 1월 −0.9, 나머지 달 +0.1~+1.5 의 결정적 계절 패턴. 지금 H2 를 쓰는 결과는 repro_biva_orig/verified(변환 none, 원본 재현)뿐 → _v1107 매매·F11 결과 무관.
- 방향: 마스터 설명·단위에 "연초 누계(YTD)" 명시, transform none 또는 DERIVED 로 월별 환산 후 pct. H1(재고, 누계 아님 — 확인)·O2(데이터 없음) 점검.
- 확실.

## 5. 교수가 물을 법한 질문
1. "입력이 그 시점에 실제로 알 수 있던 값인가?" — 공개 시점은 답 가능(검증 보고서·대조 테스트). 값의 수정(vintage)은 답 불가: B1·B2·K*·A1·F1·L9·M3 은 2025-07 최신값, 수정폭 미측정. "상한" 단서와 수정 없는 변수 분리 표 필요.
2. "월간 모델의 KOSPI·환율·금리 변수는 무엇인가?" — "마지막 거래일 하루 변화(월간 수익률과 상관 −0.06)" 라 답해야 하며 방어 불가(중대 2). 수정 후 재실행 필요.
3. "분배금·유동성·체결가 처리는?" — 분배금 미반영(4월 말 배당락 포함), 시가+5bp 고정, 평가 구간 37% 가 1억 미만 거래 — 사실대로 답할 수 있으나 "체결 가능성 미검증" 인정이 따라옴(중대 3·4).
4. "같은 데이터 버전으로 재현 가능한가?" — 부분적. data_version+lag_days_used+transforms_used+설정으로 입력 행렬 복원 가능하나 버전 폴더가 바뀌었고 마스터 해시 없음, code_version 'nogit'.
5. "미국 변수 lag 0 근거는? FRED 는 다음 날 게시 아닌가?" — 정보 존재는 규약으로 설명되나 기록된 출처(FRED)로는 그 시각에 못 받음. 출처 변경 또는 lag 1 + Δ=+1 민감도(H1 소멸) 보고.
6. "ETF 는 2006 상장인데 왜 2009-04 부터? 2007년 8일은?" — Yahoo 결측, KRX 로 메울 수 있음. 2007년 8행은 토막이라 start 로 잘라야 하는데 5개 결과는 안 잘랐다(중대 6).
