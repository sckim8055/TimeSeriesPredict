작업 파일: `/tmp/rv6_align/probe1_plant_leak.py`(누출 심기), `probe2_realdata.py`(실데이터 정렬 독립 검산), `probe3_sealed_stale.py`(봉인 폴드·낡은 입력), `probe4_perturb.py`(미래 자료 교란 → 과거 행 불변 검사). 저장소 파일은 고치지 않음(probe4 1차 실행이 `data/versions/v`, `data/versions/versions` 빈 폴더를 만들었다가 바로 지움 — 파일 없음).

## 1. 총평

타겟 정의·발표시차 정렬·기술지표·워크포워드 purging·폴드별 스케일러 등 **계산 경로 자체의 미래 참조는 찾지 못했다.** 실데이터(D/W/M 매매, 예측 stamp/release)에서 결정일 T 이후의 가격과 "T 이후 공개되는" 변수 값을 모두 바꿔도 T 이전 행의 X 가 한 열도 변하지 않았고(probe4), 11개 변수의 2024-12-30 월간 행 값이 `기준일+lag ≤ 결정일` 독립 계산과 전부 일치했다(probe2). 기술지표에 shift(−1)·중심창을 심으면 기존 랜덤워크 검사가 잡는다(방향 0.88·0.80 → 실패, probe1). 반면 **봉인(sealed) 절차는 "결정일" 기준으로만 잘려 있어** ① 알려진 경계 1행 문제 외에, ② 봉인 평가 구간의 78~82% 행이 엑셀 거시 변수가 2025-03 에서 끝난 뒤 **같은 값으로 굳은 입력**으로 평가되고, ③ 결과 화면 API 가 개발 결과에도 봉인 구간의 가격·실제 수익률 전체를 돌려줘 "개발 중 봉인 구간을 전혀 보지 않는다"는 문서 주장이 문자 그대로는 성립하지 않는다. `apply_lag=false` 가 누출 경고로 표시되지 않고 결과 json 의 `lag_days_used` 가 "적용하지 않은 lag" 를 기록하는 것도 논문 표 작성 시 오해 소지가 크다.

## 3. 확인해서 문제없던 것
- 타겟: `make_target` = open[t+1+k]/open[t+1]−1, `make_forecast_target` = v[t+k]/v[t]−1, 마지막 1+k/k 행 NaN(`calendar.py:111-171`, 시험 통과, probe2 에서 2024-12-30 값 0.10009 = 2025-01-02→02-03 시가 손계산 일치).
- 발표시차 정렬: 달력일 lag, 공개일 비거래일 → 다음 거래일, ffill 만 사용(`align_to_calendar`). 11개 변수 월간 행 독립 검산 전부 일치. 월간 변수 기준일은 전부 1일(F7·B1·K1·F11·FEDFUNDS·BOK_RATE·L2·N19 각 195/250/249/123개, 결측 월 없음 — F11 195/195 라 행 shift(−k) = k개월 뒤가 맞음).
- 미래 교란 불변(probe4): D 2764행·W 584행·M 134행·예측 stamp/release 137행 모두 X 동일, y 는 마지막 2행만 달라짐(정상).
- 기술지표: rolling·ewm(adjust=False)·diff 모두 과거 방향(`features.py`). 심은 누출(shift −1, center=True) 은 랜덤워크 검사가 잡음(0.88, 0.80).
- 워크포워드: 학습 창 끝 embargo 제거, 테스트 뒤 폴드 이동, 마지막 폴드 남은 날(`calendar.py:207-235`). 월간 ABCD: 개발 129폴드(첫 테스트 2014-04-30, 마지막 2024-12-30), 봉인 첫 폴드 학습 끝 2024-10-31(emb 2) → 봉인 학습 라벨은 봉인 가격을 쓰지 않음.
- 검증 분할: 학습 창 뒤 val_frac, 그 앞 embargo 비움(`_split_fit`). 창 모델 테스트 문맥은 입력만 붙임(라벨 없음).
- 스케일러·평균 채움은 폴드별 학습 창 통계만(테스트 기준). 변수 선택 단계는 없음.
- series(ARIMA)·levels(VECM): 학습 창으로 적합, `hist = …loc[:t]` 로 t 까지만.
- 봉인 데이터가 개발 쪽 수치에 들어가는 다른 경로: DSR 의 V(`trial_sharpe_variance`) 와 앙상블(`ensemble.py:40`) 은 봉인 결과 제외, 실험 카운터는 봉인에서 안 올림(`cli.py:63-64`). 가격 보수(`repair.py`)는 직전 공통일 비율만 사용.

## 4. 확인 못 한 것
- 실제 공개 시각(KR10Y/KR3Y 금투협 고시 시각, USDKRW Yahoo 일봉 경계, FRED 게시 시각) — 코드 밖 사실. 마스터 note 의 근거를 외부 자료와 대조하지 않음.
- 최신 수정값(vintage) 문제(B1·B2·K1~K4·F1 등) — 코드로는 확인 불가, 알려진 한계.
- 모델 내부(LightGBM/LSTM/BIVA 의 검증 사용·체크포인트 선택) 와 `engine/explain.py`.
- "예측 없는 테스트 행(포지션 유지)" 이 실제 결과 13개에서 몇 행인지(미측정).
- `api/jobs.py` 하위 프로세스가 cli 와 같은 레지스트리·데이터 버전을 쓰는지 끝까지 따라가지 않음(코드상 같은 `cli.py run`).

## 5. 교수가 물을 법한 질문
1. **"봉인 구간 정보가 개발 결과에 전혀 섞이지 않았나?"** — 지금 코드로는 "아니오" 라고 답해야 함: 마지막 결정의 정답·보유수익이 봉인 가격(월간 +10%)이고, 결과 화면에서 봉인 구간 실현 수익률을 볼 수 있었다. 고치고 재실행하면 "예".
2. **"발표시차를 지켰다는 근거는?"** — 코드 적용은 독립 검산(merge_asof 시험·probe2·probe4)으로 답할 수 있음. 값 자체는 49/65 확인·16 미확인이고 vintage 는 미해결 — 문서에 있음. 답 가능하나 한계 포함.
3. **"월간 모델의 일간 변수는 어떻게 집계했나?"** — "월 마지막 거래일 하루의 변화" 라고 답해야 하며 설계상 방어가 어렵다. 재설계 전에는 답 불가에 가까움.
4. **"봉인 평가 기간 동안 입력 변수가 살아 있었나?"** — ABCD 후보는 78~82% 행이 굳은 값 → 지금 상태로 봉인을 열면 답할 수 없음. `end` 를 잘라 봉인 구간을 2025-01~2025-05 로 줄이면(월간 5개월) 통계력이 거의 없음 — 거시 데이터 갱신이 선행돼야 함.
5. **"embargo 1+k 의 근거와 스케일러·검증 처리?"** — 답 가능(보수적 purging, 폴드별 학습 창 fit). 단 규칙 문구 "검증 구간은 transform 만" 은 코드와 달라 문구를 고쳐 두어야 함.
