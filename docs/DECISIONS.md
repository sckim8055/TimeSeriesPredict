### 2026-11-04 — 코드 점검 수정과 문서 규약
- Ridge 는 검증 분할을 쓰지 않으므로 학습 창 전체 사용(`USES_VALIDATION=False`). 이전 Ridge 수치는 85% 학습 기준이라 폐기(`results_round2.md` 정정).
- Deflated Sharpe 정식 계산: V = 같은 주기 저장 결과들의 기간 샤프 분산(실측), 왜도·첨도 실측, N = 전역 카운터. 2개 미만이면 1/(n−1) 근사.
- 분류 타겟의 DM = Brier 손실로 무정보(0.5) 대비. 결과 키는 회귀와 같은 `dm_vs_zero(_p)`, `dm_baseline="brier_vs_0.5"` 로 구분.
- 변동성 지표 연율화는 매매 주기별(252/52/12). 화면 기본 시드 = 엔진 기본(2025). `three_way_split` 제거.
- k>1 에서도 포지션은 매 주기 재결정(유지). "k기간 보유" 는 옵션 후보로만.
- **문서 규약**: 가이드 원본은 `docs/guide/*.md`. 파라미터 표·변수 표·기술지표 창은 손으로 쓰지 않고 `{{PARAMS:…}}`, `{{VARIABLE_TABLE}}`, `{{FEATURE_PRESETS}}` 자리표시자로 두어 `tools/build_guide.py` 가 코드에서 채운다(API 시작 시 자동). 수치·사례를 바꾸면 원본 md 를 고친다. 합본 `docs/GUIDE.md` 는 생성물.

- 결정(사용자 요청): 결과 상세에 '봉인 평가' 칸을 둔다. 미리보기(학습·저장 없음) → 사전 기록(선택) → 확인 2개 → 실행. 같은 설정 재개봉은 별도 확인(서버도 거절).

## 2026-11-07 — BIVA 실행에서 확인한 사실 (원본 코드는 그대로 둠)
- **VAE 의 μ·log σ² 가 ReLU 로 전부 0(죽은 ReLU) → z = ε**: 위 기록의 고른 가중치로 학습·검증 창 130개를 넣으면 ReLU 앞 값 3,120칸이 모두 음수. μ = 0, σ = 1, z 는 입력과 무관한 표준정규 잡음, KLD = 0. 학습 중 epoch 1 에서만 양수가 많았고(μ 14%, log σ² 21%) epoch 2 부터 0(203~381 epoch 에 최대 1.4% 잠시 양수 — 2026-11-07 CPU 1스레드 재기록에서는 189~401 epoch·최대 2.2%, 예측·죽은 ReLU 결론은 같음). 원인: KLD 기울기(∂/∂μ = μ ≥ 0, ∂/∂log σ² = ½(σ²−1) ≥ 0)가 ReLU 앞 값을 늘 음수 쪽으로 밀고, 모두 음수가 되면 ReLU 기울기 0. 뜻: 이 실행에서 '공통요인 z'는 정보가 없고 주기 경로 8채널 중 4채널은 잡음, 같은 창 예측의 흔들림(표준편차 3.7e−5)은 전부 이 잡음. 디코더 재구성 MSE 도 '전부 0' 기준보다 나쁨(설명 비율 −0.02).
- **검증 손실 최저 = epoch 1**(0.569; 마지막 34.4, 학습 손실 1.31 → 0.082). 500 epoch 중 epoch 1 가중치가 예측에 쓰인다. 검증 창 18개(배치 6개)라 선택이 흔들릴 수 있음.
- 첫 Adam 갱신 때 α = 1 이라 추세 경로 기울기 0 (α: 1 → 0.99).
- 원본 코드는 고치지 않는다(재현 대상). 논문에 쓸 때는 이 사실을 '원본 구현의 성질'로 적고, 다른 폴드·시드에서도 같은지 `biva_capture` 의 `vae_all`·`vae_pos` 로 확인한 뒤 일반화한다. 사용자 질문("LSTM 을 4~5번 돌리며 들어갈 때마다 다른 잡음 제거")과 코드의 대응: 인코더 LSTM 4층(34→34→17→8→4)·디코더 4층·BRITS LSTMCell 6시점×2방향은 맞지만, 층마다 '어떤 잡음을 뺀다'는 계산·손실은 코드에 없다(학습 신호는 전체 손실 하나). 명시적 분리는 이동평균(추세)과 VAE 병목·재구성·KLD 뿐.
